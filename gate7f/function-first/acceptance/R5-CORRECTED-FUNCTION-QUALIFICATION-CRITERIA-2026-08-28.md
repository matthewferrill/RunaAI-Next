# M1 R5 corrected function qualification criteria

Status: prospective criteria frozen before the corrected source commit, runtime seal, controls, or model attempts. This is M1 only and does not replace the seventeen-family roadmap.

## Purpose

R4b measured all three large models through the actual five-function application but none qualified. R5 is a fresh campaign over the corrected shared stack. It does not regrade, overwrite, pool, or resume any R4b attempt. The complete Qwen, Coder, and Gemma baseline reviews remain immutable evidence.

The corrected source must include the already reviewed provider structured-output schema, full request coverage, exact source-byte handling, provider deadline, full-plan preflight, durable mutation journal, restore-receipt grant filtering, native watchdog, owner runtime controls, and two-host transaction. A separately guarded legacy-compatibility route may preserve the current RunaAI service during migration, but it is not a scored M1 model path and may not widen the qualified M1 guard.

## Freeze and prerequisite proof

1. Commit every product, harness, deployment, and compatibility change first. Export the commit with command-scoped `core.autocrlf=false`; every source pin must equal its Git object and extracted archive bytes.
2. Run the complete repository suite with the recorded bounded file concurrency, then run the immutable Control regression serially in a new owned stage with actual disposable PostgreSQL, Qdrant, QuickJS/MXC and Windows isolation. Both require zero failures and zero skips.
3. Create one prospective runtime seal binding the source commit/archive, Node, dependency lock, Qdrant, three exact large-model artifacts, Nomic, BGE, hardware policy, fixed cases, fixed budgets, and grading policy.
4. Run all twelve model-free controls afresh against that same source and seal. Actual browser checkpoints must be independently observed; fixture DOM or HTTP completion is not browser proof.
5. Prove Home owner lifecycle, queue/processing observation, TLS guard, idle unload, crash/restart, zero-residency cleanup, power restoration, and complete caller closure. Legacy compatibility evidence remains separately identified.

## Fixed matched campaign

- Candidates: exact pinned Gemma 4 26B A4B, Qwen3-Coder 30B A3B, and Qwen 3.6 27B MTP only.
- Functions: chat/continuity, approved-source research, bounded code work, conversational governed action, and deeper review.
- Cases: the unchanged eight cases per function, three repetitions, 40 journeys and 120 attempted slots per candidate; 360 total attempted slots.
- Execution: one large model resident at a time under the same Home power/temperature/memory policy, with actual application requests and the same fixed per-role budgets. No pooled reruns, selective replacement, denominator reduction, expected-answer tuning, or role-specific stack changes.
- Evidence: create-only started/raw/record files for every slot, actual PostgreSQL/LangGraph/native receipts, and independently bound browser acknowledgements where required. Invalid, timed-out, incomplete, or interrupted attempts remain in the denominator.

## Acceptance and selection

Independent semantic review must classify every attempt and inspect all critical model-behavior cases. A candidate qualifies for a function only with at least 22 of 24 acceptable attempts, zero definite critical failures, complete evidence, and all common controls green. Driver completion is never a pass.

Record an explicit disposition for every candidate/function pair. A single primary model may be deployed only for the functions it qualified. Mixed role routing is permitted only if deterministic application-owned routing, model availability/failure behavior, privacy separation, continuity, and rollback are implemented and tested before selection; model text cannot select or authorize its route.

If a role fails because of a shared product defect, fix the shared stack prospectively and start a new fully sealed campaign. If it fails because of model behavior, retain the failure and select another qualified candidate or defer that role. Do not weaken governance, containment, evidence, or customer semantics to improve scores.

## Deployment boundary

R5 does not authorize production routing by itself. Only after qualification, independent review, installed Home/runtime proof, legacy-preservation proof, and a complete rollback rehearsal may the exact successor be deployed through the owner transaction. Production admission remains closed until final reconciliation. Human testing begins only after ordinary sign-in, chat/code continuity, and selected function paths are ready on the rollback-protected successor.
