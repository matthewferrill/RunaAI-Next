## Triage and RCA: what happens if something fails

1. **Stop the affected stage immediately.** Do not advance its successors or retry unchanged. Preserve the original
   attempt, stage/case ID, safe error classification, source/runtime identity and actual before/after effects.
   Stop only owned work; if effect/cleanup is uncertain, retain the object and reconcile it before any repeat.
2. **Classify from evidence:** application; environment/runtime; harness/operator; publication/witness/browser;
   dependency/service outage; model behavior; or unknown. Record severity separately. Review findings before
   execution are not failed actual rounds. Expected denial tests are not incidents. Do not charge a model for
   requests it never received or valid responses the application mishandled.
3. **Prioritize:** safety, privacy, integrity, data loss and uncertain effects block dependent work/release immediately.
   Broken required workflows or methods block their stage. Cosmetic/nonessential findings may be logged separately
   without blocking independent safe work; they do not vanish or receive an invented pass.
4. **Diagnose the actual cause.** Check the fix register; compare exact actual host/API behavior with official docs,
   known issues and installed source. Use the smallest read-only or disposable reproduction that distinguishes
   hypotheses. Missing evidence stays unknown; do not run a whole workflow to rediscover an earlier setup failure.
5. **Do full causal analysis:** what failed; why technically; why that assumption/code entered the design; why review
   and verification missed it; which active callers share it. Separate facts, inference and unknowns. Assign an owner,
   corrective action, preventive action and observable effectiveness check. Do not reopen retired mock history.
6. **Design the correction:** cite the established remedy and version applicability. If custom code is unavoidable,
   record alternatives checked, why unsuitable, minimal scope, rollback and replacement condition. Fix the shared
   cause across confirmed active callers, not every hypothetical future feature. Preserve security and thresholds.
7. **Review and resume:** independent review checks both fix and measurement method; commit exact corrected inputs;
   verify cheap applicable prerequisites, then resume only the failed/unconsumed stage. If only publication failed,
   recover and publish the existing authenticated result where possible rather than repeating the effect.
8. **Repeated failure reopens the cause:** the same cause after correction invalidates that fix's reuse status and
   returns the affected lane to diagnosis; no automatic retry loop or increased timeout to hide it. If a new cause
   emerges, verify whether the same upstream readiness omission explains it before authorizing another run.
9. **Close honestly:** append corrected evidence and affected scope to the original RCA and fix register. Mark case
   closure separately from systemic prevention, which requires subsequent applicable work to demonstrate effectiveness.

One compact RCA entry contains: incident ID; stage; severity/category; exact environment; expected/observed behavior;
effects/cleanup; causal chain and uncertainty; analogous callers; official source/known fix; correction and prevention
owner; changed files/commit; independent verdict; affected-only result; rollback; recurrence status.
An outage receives documented upstream/service evidence when available, not a fabricated application patch.
